## Contenu de l'onglet

**Réglages modifiables** (écrits dans `horizon.json` au moment d'« OK ») :

- **Channel** : liste éditable `stable`, `beta`, `pinned` ;
- **Client version** : versions installées par le launcher Horizon, ou vide
  pour « la plus récente installée » ;
- **Preparer version** : même liste, même règle ;
- **Start in fullscreen** : case à cocher.

**Valeurs en lecture seule** (contrat du binaire épinglé) :

- Minecraft (`26.3`), `launch_api`, `output_version`, `native_hooks_api` ;
- chemin des ressources et état « prepared / not prepared ».

L'onglet générique « Settings » de Prism est conservé : il porte la taille de
fenêtre et les options quick-play utilisées par le lancement.

## Persistance

Chaque modification passe par les setters de `HorizonInstance`, qui écrivent
`horizon.json` via `saveHorizonJson()` :

```json
{
  "channel": "stable",
  "clientVersion": "nightly-2026-11-13-9f42064",
  "preparerVersion": "nightly-2026-11-13-9f42064",
  "fullscreen": true,
  "minecraft": "26.3",
  "pins": { "launch_api": "0.1.0", "output_version": 4, "native_hooks_api": 415 }
}
```

Un champ vide (`clientVersion` ou `preparerVersion`) laisse la résolution
automatique choisir la version installée la plus récente.

## Plein écran

`HorizonLaunchStep` transmet `--fullscreen` quand `horizon.json` contient
`"fullscreen": true`, et n'envoie alors ni `--width` ni `--height`. Sinon il
utilise `MinecraftWinWidth` / `MinecraftWinHeight` de Prism.

  -d "$PWD/testdata" --show HorizonTest --alive

- `testdata/instances/HorizonTest/horizon.json` est inchangé après ouverture ;
- le lancement M4 (préparation + client) n'est pas modifié.

## Écarts assumés par rapport au plan initial

- pas de **render distance** ni de **vsync** : le contrat `--launch-api` de
  Horizon n'expose que `--fullscreen`, `--width` et `--height` ; inventer des
  réglages Prism qui ne seraient pas transmis serait trompeur ;
- le **channel** est informatif pour l'instant : il n'y a pas encore de
  téléchargement/mise à jour de versions (M6) ;
- la page ne propose pas encore de bouton « Prepare / Repair » : la
  préparation reste déclenchée par « Play » (M4).
