# M4 — préparation automatique des ressources

Branche : `horizon/m4` (dans `fork/PrismLauncher`), basée sur `horizon/m3`
@ `86ca187`.

Objectif : une installation neuve peut lancer Horizon sans terminal. Avant
chaque lancement, Prism vérifie les ressources avec `horizon-prepare --check`
et ne prépare que si nécessaire, en affichant la progression.

> ✅ **Validé** les 16–17/11/2026 avec le vrai `horizon-prepare` : contrôle
> à jour en 0,4 s, préparation à froid en 67 s (223 Mo), puis lancement réel
> de `horizon-client` sans erreur.

## Flux de lancement

```
HorizonPrepareStep → HorizonNotPrepared → HorizonLaunchStep
```

### 1. Vérification

`horizon-prepare --check --output <instance>/horizon/resources`

- sortie 0 → ressources à jour, étape suivante ;
- sortie ≠ 0 → les lignes `… missing: horizon-prepare <nom>` sont classées :
  - **optionnelles** : `packs`, `panorama`, `fonts`, `languages`, `sounds` ;
  - **requises** : tout le reste.

Si seuls des extras optionnels manquent, le lancement continue : Horizon
démarre sans sons, avec le panorama classique, etc.

### 2. Préparation

Seulement si un gap requis existe (ou si le dossier n'existe pas) :

```
horizon-prepare --prepare \
  --output <instance>/horizon/resources \
  --prism-dir <racine Prism ou instance> \
  --java-home <runtime Java 25> \
  --progress json
```

- `--prism-dir` : la racine de données Prism quand elle contient `meta/`
  (JSON de version 26.3, bibliothèques Maven, assets), sinon la racine de
  l'instance. Le client jar Prism sert de côté serveur : **aucun jar serveur
  n'est téléchargé**.
- `--java-home` : Prism `JavaPath` si le runtime est Java 25, sinon un runtime
  géré par Prism (`<data>/java/*/release`), sinon le JDK 25 système via
  `/usr/libexec/java_home -v 25` (macOS). Omis si aucun ne correspond.
- `--complete` n'est **pas** passé : les extras optionnels ne sont pas
  téléchargés automatiquement.

Les événements `--progress json` (`{"fraction":…,"message":…}`) pilotent la
barre de progression et le statut de la tâche ; les erreurs
(`{"error":…}`) sont remontées dans le log.

### 3. Re-vérification

Après un code de sortie 0, un second `--check` valide le résultat :

- gaps requis restants → échec avec le détail ;
- seulement des extras optionnels → succès, avec un avertissement listant les
  extras manquants.

## Résolution de `horizon-prepare`

Même logique que `horizon-client` (M3) :

1. `preparerPath` dans `horizon.json` (absolu ou relatif à l'instance) ;
2. `versions/<preparerVersion>/horizon-prepare` du launcher Horizon ;
3. la dernière version installée qui contient le binaire ;
4. `horizon-prepare` dans `PATH`.

## Test effectué

Deux scénarios avec le vrai `horizon-prepare` (nightly 2026-11-13 ·
9f42064), dans `fork/testdata` :

### 1. Ressources déjà préparées

```
HorizonPrepareStep   démarré à 1,387 s
HorizonPrepareStep   réussi  à 1,804 s   (0,4 s, `--check` seul)
HorizonNotPrepared   réussi
HorizonLaunchStep    réussi  à 9,882 s
```

`--check` ne signale que les cinq extras optionnels ; aucune préparation
n'est relancée. Le lancement réel rend deux frames et écrit un
`smoke-report.json` sans erreur.

### 2. Ressources absentes (préparation à froid)

`horizon/resources` déplacé hors de l'instance, puis « Play » :

```
HorizonPrepareStep   démarré à 1,387 s
HorizonPrepareStep   réussi  à 68,678 s   (67,3 s de préparation)
HorizonNotPrepared   réussi
HorizonLaunchStep    réussi  à 74,331 s
```

- ressources produites : **223 Mo** ;
- `horizon-prepare --check` final : seuls `packs`, `panorama`, `fonts`,
  `languages`, `sounds` manquent (extras optionnels) ;
- `smoke-report.json` : `{"frames":2,"error":null}`.

Dans ce bac à sable, `fork/testdata` n'a pas de `meta/` : `--prism-dir` a donc
reçu la racine de l'instance, et `horizon-prepare` a retrouvé Minecraft via
l'installation liée du launcher Horizon. Avec une vraie racine Prism pourvue
de `meta/`, c'est elle qui est transmise. `--java-home` a été résolu vers le
JDK 25 système (`/usr/libexec/java_home -v 25`), faute de `JavaPath` Prism
configuré dans ce bac à sable.

> ⚠️ Comme en M1/M3, Prism exige un compte Microsoft propriétaire de
> Minecraft avant de créer la tâche de lancement. Ces tests ont utilisé un
> **patch local temporaire** de `LaunchController` (session hors-ligne pour
> `InstanceType=Horizon`) et deux flags de test (`--frames 2
> --smoke-report`), tous **retirés** : le code M4 commité est inchangé.

## Ce que M4 ne fait pas

- pas de bouton « Prepare / Repair » dans la page de réglages de l'instance
  (la préparation est déclenchée par « Play ») ;
- pas de `--complete` ni de téléchargement des extras optionnels ;
- pas de mise à jour automatique des binaires Horizon (M6) ;
- pas de vérification de signature des binaires.
